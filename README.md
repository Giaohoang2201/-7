# 과제 - 07: 인접 행렬과 인접 리스트의 성능 비교

## 1. 개요

`graph_compare.c`는 정점이 100개(번호 0 ~ 99)인 무방향 단순 그래프(자기 자신을 잇는 간선과 중복 간선 없음)를 두 종류 무작위로 생성한다.

| 그래프 | 정점 수 V | 간선 수 E | 밀도 E / (V(V-1)/2 = 4950) |
|---|---|---|---|
| Sparse (희소) | 100 | 100 | 약 2.0 % |
| Dense (밀집) | 100 | 4000 | 약 80.8 % |

각 그래프는 간선 목록을 **한 번만** 생성한 뒤 인접 행렬과 인접 리스트에 **똑같이** 넣는다. 따라서 두 표현 방식은 항상 같은 그래프이다. 프로그램은 `verify_same` 함수로 두 표현이 같은 그래프인지 검증하고, 인접 정점 집합도 서로 비교한다. 두 검사 모두 `OK` / `동일`로 나왔다.

컴파일과 실행 방법:

```bash
gcc -O2 -Wall -o graph_compare graph_compare.c
./graph_compare          # 기본 seed 12345
./graph_compare 2026     # seed를 바꾸면 다른 그래프로 실험할 수 있다
```

아래 결과의 전체 출력은 `output.txt`에 저장되어 있다.

## 2. 구현 방법

### 인접 행렬
```c
typedef struct { unsigned char m[100][100]; } AdjMatrix;
```
한 칸에 1바이트를 사용한다. 간선 (u, v)를 넣을 때 `m[u][v] = m[v][u] = 1`로 설정한다.

### 인접 리스트
```c
typedef struct Node { int vertex; struct Node *next; } Node;      // 16 바이트
typedef struct { Node *head[100]; int nodeCount; } AdjList;       // 808 바이트
```
정점마다 단방향 연결 리스트를 둔다. 간선 (u, v)를 삽입하면 u의 리스트에 v를, v의 리스트에 u를 리스트 맨 앞에 넣으므로 간선 하나당 **노드가 2개** 필요하다.

### 메모리 계산 방법
- 인접 행렬: `sizeof(AdjMatrix)` = 100 × 100 × 1 = **10,000 바이트** (간선 수와 무관).
- 인접 리스트: `sizeof(AdjList)` + `nodeCount × sizeof(Node)` = 808 + 2E × 16 바이트.
  - 808바이트는 정점별 head 포인터 100개(100 × 8 = 800)와 `nodeCount`(4바이트 + 정렬 패딩 4바이트)이다.
- 난수 생성용 임시 배열 `tmp`와 간선 목록 `edges`는 그래프 메모리에 포함하지 않았다(과제 조건).

### 비교 횟수 기준
자료구조의 원소를 한 번 확인할 때마다 1회로 센다.

| 연산 | 인접 행렬 | 인접 리스트 |
|---|---|---|
| 연결 여부 확인 (u, v) | `m[u][v]` 확인 → 1회 | u의 리스트를 v가 나오거나 끝날 때까지 확인 → 확인한 노드 수 |
| 간선 삽입 (u, v) (존재하지 않는 간선) | `m[u][v]` 확인 → 1회 | 중복 확인을 위해 u의 리스트 전체 확인 → deg(u). 이후 두 리스트의 맨 앞에 삽입하므로 추가 비교 없음 |
| 간선 삭제 (u, v) (존재하는 간선) | `m[u][v]` 확인 → 1회 | u의 리스트에서 v를 찾는 횟수 **+** v의 리스트에서 u를 찾는 횟수 |
| 정점 u의 인접 정점 출력 | `m[u][0..99]` 확인 → 100회 | u의 리스트 노드를 모두 확인 → deg(u) |

`m[u][v] = 0/1` 대입, `malloc`/`free`는 원소를 "확인"하는 동작이 아니므로 비교 횟수에 포함하지 않았다.

## 3. 측정 결과 (seed = 12345)

두 표현 방식에는 **같은** 삽입 간선, 삭제 간선, 연결 확인 정점 쌍, 인접 정점 출력 대상 정점을 사용했다.

### 3.1 실험 대상

| | Sparse | Dense |
|---|---|---|
| 삽입 간선 (존재하지 않음) | (97, 39) | (21, 80) |
| 삭제 간선 (존재함) | (30, 79) | (40, 33) |
| 연결 확인 정점 쌍 | (40, 74) → 간선 없음 | (30, 39) → 간선 없음 |

1회 측정값은 선택된 정점(특히 그 정점의 차수)에 따라 크게 달라질 수 있다. 그래서 무작위로 고른 정점 쌍으로 1000회 반복(삽입·삭제 후에는 그래프를 원래대로 복구)하여 평균을 구했고, 분석에는 이 평균도 함께 사용했다.

| 연산 | Sparse – 행렬 | Sparse – 리스트 | Dense – 행렬 | Dense – 리스트 |
|---|---:|---:|---:|---:|
| 간선 삽입 | 1.00 | 1.88 | 1.00 | 79.22 |
| 간선 삭제 | 1.00 | 4.03 | 1.00 | 82.58 |
| 연결 여부 확인 | 1.00 | 2.00 | 1.00 | 48.55 |
| 인접 정점 출력 | 100.00 | 2.00 | 100.00 | 80.18 |

## 4. 분석

### 4.1 메모리 사용량

- 인접 행렬은 그래프가 희소하든 밀집하든 항상 **10,000바이트**이다. 크기가 V²에 의해서만 결정되고 간선 수 E와는 무관하기 때문이다.
- 인접 리스트는 간선 수에 비례하여 늘어난다: 808 + 32E 바이트(무방향 간선 하나가 노드 2개 × 16바이트). E = 100이면 **4,008바이트**, E = 4000이면 **128,808바이트**이다.
- 따라서 희소 그래프에서는 인접 리스트가 인접 행렬보다 약 2.5배 적게 쓰고, 밀집 그래프에서는 오히려 약 **12.9배** 더 많이 쓴다.
- 메모리 손익분기점은 808 + 32E = 10,000, 즉 E ≈ 287개(밀도 약 5.8 %)이다. 그보다 간선이 많으면 인접 행렬이 더 작다.
- 참고: 노드 하나는 16바이트(데이터 4 + 패딩 4 + 포인터 8)인 반면 행렬 한 칸은 1바이트이다. 행렬을 `int`(4바이트/칸)로 만들면 40,000바이트가 되어 손익분기점이 E ≈ 1,220 정도로 올라가지만, 어느 쪽이 유리한지에 대한 경향은 같다.

### 4.2 희소 그래프 (V = 100, E = 100, 평균 차수 = 2)

- **연결 확인 / 삽입 / 삭제**: 인접 행렬은 인덱스로 바로 접근하므로 항상 1회(O(1))이다. 인접 리스트는 각 리스트가 매우 짧아(평균 2개) 몇 번이면 충분하다: 연결 확인 2.00, 삽입 1.88, 삭제 4.03. 삭제가 더 많은 이유는 **양쪽** 정점의 리스트에서 노드를 찾아야 하기 때문이다. 차이는 몇 회에 불과해 사실상 무시할 만하다.
- **인접 정점 출력**: 가장 큰 차이가 나는 연산이다. 인접 행렬은 인접 정점이 3개뿐인 정점 91을 찾기 위해서도 한 행 100칸을 모두 확인해야 하지만(100회), 인접 리스트는 노드 3개만 확인하면 된다. 평균으로는 100회 대 2회로 **약 50배** 차이가 난다. 행렬은 대부분의 칸이 0이라 낭비가 크다.
- **메모리**: 인접 리스트가 더 작다(4,008 대 10,000 바이트).
- **결론**: 희소 그래프에서는 인접 리스트가 메모리와 인접 정점 출력에서 확실히 유리하고, 간선 조회 연산에서는 인접 행렬보다 몇 회 더 쓰는 정도로 손해가 거의 없다.

### 4.3 밀집 그래프 (V = 100, E = 4000, 평균 차수 = 80)

- **연결 확인 / 삽입 / 삭제**: 인접 행렬은 여전히 1회이다. 반면 인접 리스트는 각 리스트가 평균 약 80개로 길어져 비교 횟수가 크게 늘어난다: 삽입 80회(평균 79.22), 삭제 50회(평균 82.58), 연결 확인 79회(평균 48.55). 간선이 **존재하지 않을 때**(위의 1회 측정 사례)는 u의 리스트 전체를 확인해야 결론이 나고, 간선이 존재할 때는 평균적으로 리스트의 절반 정도만 확인하면 되므로, 평균 48.55는 두 경우 사이의 값이다. 연결 리스트에는 임의 접근이 없어 O(deg(u))가 걸리기 때문이다.
- **인접 정점 출력**: 두 방식이 거의 비슷해졌다(행렬 100회, 리스트 평균 80.18회; 평균 차수가 약 80이므로 당연한 결과이다). 행의 대부분이 실제 간선이라 행렬의 낭비가 사라졌고, 인접 리스트의 장점도 거의 없어진다. 비교 횟수에는 드러나지 않지만, 연결 리스트의 노드는 메모리에 흩어져 있어 연속된 배열을 읽는 행렬보다 캐시 효율이 낮다는 점도 불리하게 작용한다.
- **메모리**: 인접 리스트는 간선마다 16바이트 노드를 2개씩 저장하므로 128,808바이트로, 인접 행렬(10,000바이트)의 약 12.9배이다.
- **결론**: 밀집 그래프에서는 인접 행렬이 메모리와 조회/삽입/삭제 속도 모두에서 우세하고, 인접 정점 출력에서도 뒤지지 않는다.

### 4.4 어떤 경우에 무엇을 쓰는 것이 적절한가

| 상황 | 적합한 표현 | 실험에서 얻은 근거 |
|---|---|---|
| 희소 그래프(E ≪ V²), V가 큰 경우 | **인접 리스트** | 메모리가 V² 대신 E에 비례하고, 인접 정점 출력이 V 대신 deg(u)만큼만 걸림 |
| 희소 그래프에서 BFS, DFS, 다익스트라 등 순회 알고리즘 | **인접 리스트** | "u의 모든 인접 정점 방문"을 반복하므로 인접 리스트는 O(V + E), 인접 행렬은 O(V²) |
| 밀집 그래프(E가 V²/2에 가까움) | **인접 행렬** | 메모리가 훨씬 작고(10,000 대 128,808 바이트), 간선 조회가 항상 1회 |
| "간선 (u, v)가 있는가?" 조회나 간선 삽입/삭제가 매우 잦은 경우 | **인접 행렬** | O(1) 대 O(deg(u)). 밀집 그래프에서 차이가 가장 큼(1회 대 약 80회) |
| V가 작고 고정되어 있으며(예: 이 과제의 V = 100) 구현을 단순하게 하고 싶은 경우 | **인접 행렬** | V² 메모리 부담이 작고 코드가 간단함 |
| V가 매우 큰 경우(수만 개 이상) | **인접 리스트** | V² 크기의 행렬은 메모리에 올리기 어려움 |
| 간선 수가 계속 변하거나 미리 알 수 없는 경우 | **인접 리스트** | 간선마다 노드를 할당하므로 V²를 미리 잡아 둘 필요가 없음 |

정리하면, 그래프의 **밀도**가 어떤 표현이 좋은지를 결정한다. E = 100(밀도 약 2 %)에서는 인접 리스트가 메모리를 약 2.5배 덜 쓰고 인접 정점 출력이 약 50배 빠르다. E = 4000(밀도 약 81 %)에서는 인접 행렬이 메모리를 약 12.9배 덜 쓰고 간선 조회/삽입/삭제가 약 50 ~ 80배 빠르다. 어느 한 쪽이 항상 우수한 것은 아니며, 인접 행렬은 메모리를 더 쓰는 대신 조회 속도를 얻고, 인접 리스트는 조회 속도를 일부 포기하는 대신 희소 그래프에서 메모리를 아낀다.

## 5. 한계

- 1회 측정값은 무작위로 선택된 정점 쌍에 따라 달라지므로, 결론은 1000회 평균 표를 함께 참고하여 도출했다.
- 인접 리스트는 맨 앞 삽입을 가정하고 위 2절의 기준으로 비교 횟수를 센다. 기준이 달라지면(예: 삽입 시 중복 확인을 하지 않으면 0회, 리스트 끝에 삽입하면 deg만큼 추가) 구체적인 숫자는 달라지지만 두 방식을 비교한 경향은 같다.
- 메모리는 `sizeof` 기준이며(행렬은 `unsigned char` 사용) `malloc`이 노드마다 붙이는 내부 관리 공간은 포함하지 않았다. 실제 인접 리스트 사용량은 이보다 조금 더 크다.
